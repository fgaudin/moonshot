# Moonshot i18n: instructions for translating a source file into French and German

The app (vanilla JS, no build step, served at http://localhost:8642, open from `index.html`) is English in the
code. We add French (fr) and German (de). Read `js/i18n.js` first (40 lines): it defines `T`, `N`, `I18N`.

## How translation works

- `` T`English text` `` returns the translation of that exact English string in the current language, or the
  English if none exists. Interpolations become numbered placeholders in the key:
  `` T`Range ${r} m from ${name}` `` has key `Range {$0} m from {$1}`; the translation must contain the same
  placeholders (order may change): `'À {$0} m de {$1}'`.
- `T(str)` / `T('Hello {$0}', x)`: same, as a function; use it for strings held in variables.
- `` N`English` `` / `N('English')`: returns the English unchanged. It only **marks** a string so the checker can
  extract it. Use N for strings defined at module load time (data tables, presets, chapter titles…), and call
  `T(value)` where the value is displayed.
- **T must run at display time, never at module load time.** Language can change at runtime; the router then
  re-renders the current page. Anything translated once at load would stay in the old language.
- Dictionaries: `js/i18n/fr/<basename>.js` and `js/i18n/de/<basename>.js`, where `<basename>` is the source file
  name without `.js` (e.g. `js/ch/newton.js` → `js/i18n/fr/newton.js`). Format:

```js
/* Newton & Gravity (js/ch/newton.js) — français */
I18N.add('fr', {
  'English key exactly as T builds it': 'Traduction',
});
```

## What to do in your assigned source files

1. Wrap every piece of **user-visible English** with T (or N + T): headings, paragraphs, list items, lede,
   eyebrows, book reference chips, buttons, labels, `<option>` text, `aria-label`, `title`, slider labels
   (`UI.slider({ label: ... })` → `label: T`...``), readout `<dt>` labels, units that are words
   (`'min'`, `'h'`, `'s'` stay; `'t TNT'`, `'rad or °'` → translate), canvas `fillText` strings, badges, toasts,
   messages, `Sym.where` custom rows and notes, primer boxes, objectives, everything.
2. Granularity: one T per paragraph / list item / heading / label. Keep inline HTML (`<b>`, `<i>`, `<sub>`,
   links) and inline TeX (`\\( … \\)`) **inside** the string; translators keep them. Don't split sentences.
3. Display equations (`<div class="eq">\\[ … \\]</div>`): leave them alone unless they contain words in
   `\\text{…}` / `\\mathrm{…}` words (e.g. "gravity loss", "constant"); then wrap the whole TeX string in T and
   translate only the words.
4. Interpolated numbers: keep them as `${…}` inside the T template so they become placeholders.
   Example: `` `<dt>Range</dt><dd>${UI.fmt(r, 1)} m</dd>` `` → `` `<dt>${T`Range`}</dt><dd>${UI.fmt(r, 1)} m</dd>` ``.
5. **Logic that depends on displayed text must not break.** Example: `js/ch/newton.js` compares
   `b.textContent === 'Circular'`; replace with a `data-*` attribute check. Grep your files for comparisons
   against English strings, `.replace(` on display names, `textContent ===`, etc.
6. Do **not** change the English wording. The English output of the app must stay byte-for-byte identical
   (apart from refactors needed by point 5).
7. Formatting: `UI.fmt` already prints decimal commas in fr/de. For numbers printed with `toFixed` directly in
   visible text, wrap them: `UI.dec(x.toFixed(2))`.
8. Do not edit files outside your assignment. In particular never edit `js/i18n.js`, `js/app.js`, `js/ui.js`,
   `index.html`, `css/style.css`, or another agent's files or dictionaries.

## Escaping (important)

Keys are the **cooked** strings. Source `` T`Use \\(v\\) here` `` (inside a JS template, `\\(` is a
backslash + paren) has the key `Use \(v\) here`. In the dictionary file you write a normal JS string, so the key
is written `'Use \\(v\\) here'`. Same for the translation. Use the checker; it parses your source with acorn and
reports any key you missed or mistyped.

## Checking (required before you finish)

```sh
node tools/i18n-check.js keys js/ch/newton.js              # list the keys your file uses
node tools/i18n-check.js check fr js/ch/newton.js          # must end with: TOTAL missing in fr: 0
node tools/i18n-check.js check de js/ch/newton.js          # same for de; also no PLACEHOLDER MISMATCH lines
node --check js/ch/newton.js; node --check js/i18n/fr/newton.js; node --check js/i18n/de/newton.js
```

Optional smoke test in a browser (puppeteer-core is installed in `tmp/pp`, Chromium at `/snap/bin/chromium`):
set `localStorage['moonshot:lang'] = '"fr"'`, load `http://localhost:8642/#<chapter>`, check for page errors and
`I18N.missing` (a Set of keys that were requested but not found).

## Style

- French: vouvoiement ("vous"). Typographic apostrophe ’, guillemets « … » with narrow no-break spaces
  (U+202F) inside, and a narrow no-break space before ; : ! ?. Decimal comma in prose ("7,8 km/s"), thousands
  separated by a narrow no-break space ("384 400 km").
- German: "du" (informal, as in learning apps), capitalised Du not needed. Quotes „ … “. Decimal comma.
  Thousands with narrow no-break space or dot-free spacing ("384 400 km").
- Natural, fluent, precise technical language, the register of a good textbook (Sellers / BMW translated by a
  professional). Short, direct sentences, like the English. No em-dash asides.
- Keep unchanged: proper nouns, mission names, vehicle and stage names (Saturn V, S-IC, S-IVB, CSM, LM,
  Columbia, Eagle), acronyms (TLI, LOI, TEI, MCC, COAS, RCS, SPS, DPS, APS, GET, TWR, Δv, I<sub>sp</sub>),
  program names (P63, P64, P66), alarm codes, book titles (Sellers, *Understanding Space*; Bate, Mueller & White,
  *Fundamentals of Astrodynamics* / BMW), units and symbols, keyboard key names.
- People are mentioned by name; Vega (the fictional instructor) has no stated gender: keep it neutral.
